About the APIs

This dashboard is powered by two free, open, no-auth public APIs. Here's what each one does, how they're called, and the data model behind the scenes.

Source 01

jolpi.ca →

Jolpica F1 API

Jolpica is an open-source API that maintains backwards compatibility with the now-deprecated Ergast API. It covers every Formula 1 season from 1950 onwards — race results, qualifying, driver and constructor standings, lap times, pit stops, and more. No account or API key required.

Base URLhttps://api.jolpi.ca/ergast/f1
AuthNone
Rate limit200 req / hour
FormatJSON
Coverage1950 → present
Page size30 rows (hard cap)

Endpoints used

GET
/{year}/results/?limit=30&offset=0

Race results for every round — paginated. Each page returns up to 30 driver-result rows (not races). A 24-race season has ~480 rows (24 × 20 drivers), requiring 16 paginated requests merged by round number.

GET
/{year}/driverstandings/

Final driver championship standings — position, points, wins, nationality, and team for every classified driver.

GET
/{year}/constructorstandings/

Final constructor championship standings — position, points, and wins for each team.

GET
/{year}/qualifying/?limit=30&offset=0

Qualifying results per round — Q1, Q2, Q3 times and grid positions. Also paginated by driver-result row.

Pagination note

The limit parameter is ignored for values above 30 — Jolpica always returns a maximum of 30 rows per page regardless. MRData.total tells you the total row count, not the race count. This dashboard paginates through all pages in parallel and merges results by round number to reconstruct complete race objects.

Source 02

openf1.org →

OpenF1 API

OpenF1 provides real-time and historical session-level data from the official F1 timing feed. It includes granular lap-by-lap data, car telemetry (throttle, brake, DRS, speed), weather, tyre compounds, race control messages, and pit stop data. No authentication required.

Base URLhttps://api.openf1.org/v1
AuthNone
Rate limitGenerous (no hard limit published)
FormatJSON
Coverage2023 → present

Endpoints used

GET
/sessions?year={year}&session_name=Race

Returns all race sessions for the given year, each with a unique session_key. The last session in the list is used as the reference for pit stop data.

GET
/pit?session_key={key}

All pit stop events for a session — driver number, lap number, and duration in seconds. Used to compute total stops, average and fastest durations, and max stops per driver.

Coverage note

OpenF1 data is available from the 2023 season onwards. For seasons before 2023 the pit stop block in the dashboard will show "no data" — this is expected. The Jolpica results data (race winner, lap counts, fastest lap) still loads normally for all seasons back to 2000.

Available but not yet used

OpenF1 exposes much richer data that could extend this dashboard further:

Car telemetry Lap times Tyre compounds Weather Race control messages Driver position (live) Team radio Stints

Architecture

How data flows

On season select, four Jolpica requests fire in parallel using Promise.all — race results (paginated), driver standings, constructor standings, and qualifying (paginated). Results are cached in memory so switching back to a previously loaded season is instant.

OpenF1 pit data loads asynchronously after the main render — it fills in the pit stop block without blocking the rest of the page. All data is fetched fresh from the API on each page load; nothing is stored server-side.

01

Season select

Four Jolpica requests fire in parallel via Promise.all

02

Pagination merge

Race results pages are merged by round number into complete race objects

03

Render

Hero, metrics, tabs, right column, and charts are rendered from the merged data object

04

Pit data (async)

OpenF1 session + pit requests fire after main render — fills in the pit block on completion

05

Cache

Season data is stored in memory — re-selecting a season skips all fetches

Running locally

Local server required

Browsers block cross-origin API requests from file:// URLs (CORS policy). You must serve the project through a local HTTP server. Any of these work:

PY
python3 -m http.server 8080
NPX
npx serve .
VSC
Right-click index.html → Open with Live Server

Then open http://localhost:8080 in your browser.
